The problem

Ocean data is abundant.
Answers aren't.

ISRO, INCOIS and global agencies publish enormous volumes of Earth Observation data daily — SST, chlorophyll, weather, tides, cyclone alerts. Fishermen, researchers and coastal authorities still can't easily ask "is it safe to go out tomorrow?" and get a synthesized, evidence-based answer.

"Where is the nearest Potential Fishing Zone today? Is it safe to venture into the sea tomorrow morning?" — the exact questions ISRO's brief asks us to answer conversationally, in Indian regional languages, with reasoning attached.
What we're building

Five features, one agent platform.

Scoped deliberately out of ISRO's full brief for a working, demonstrable hackathon build — not a slide of everything the platform could theoretically do.

01 / LANG

Hindi + Tamil conversation

Bhashini API for translation in/out; agent reasoning stays in English underneath, so language is a wrapper, not core complexity.

02 / PFZ

Nearest PFZ by GPS

Live INCOIS advisory data, matched to the closest landing centre from device location, resolved to a plottable zone.

03 / CHAT

Agentic reasoning

Planner agent decomposes a query, routes to specialist agents, and shows its evidence trail — not just an answer.

04 / RISK

Hazard zones

High-wave, cyclone and lightning advisories overlaid on the map, cross-referenced against the fisherman's location.

05 / GEO

Geofencing alerts

Live device location checked against EEZ / restricted-zone polygons; proactive warning on approach, no query needed.

Data pipeline — verified this week

A real, working INCOIS integration

Not a mock dataset. We reverse-engineered INCOIS's Marine Fisheries Advisory session flow and pulled live, dated PFZ data for six coastal sectors.

01

Session bootstrap

GET the TextDataHome landing page first — establishes the JSESSIONID cookie the data endpoint requires.

02

Sector fetch

GET /MarineFisheries/TextData?secid=SECxxx with that session + referer — returns the live advisory HTML table.

03

Parse & normalise

pandas.read_html extracts the table; bearing, distance-range and DMS coordinates are converted to a clean per-village schema.

04

Geo-resolve

Origin lat/long + bearing + distance → actual plottable PFZ boundary points, via geodesic destination calculation.

05

Cache for offline

Result set stored client-side — this is the exact bundle a fisherman syncs before losing signal at sea.

Built for the real coast

Offline-first, because signal ends 15km out

On land

Sync before departure

At the harbour, full signal: app pulls today's PFZ, weather and alerts into local cache. Shows exact sync timestamp.

At sea

Runs on cached data

Beyond coverage, the PWA serves everything from Cache Storage / IndexedDB — no network calls, no failure state.

Known limit

New alerts still need SMS

A cyclone forming after departure can't reach a phone with no signal — stated honestly, not hidden in the pitch.
